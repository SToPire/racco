# 聊天图片输入：首版设计

状态：已实现。决策摘要见 [Agent Note](../../.agents/notes/implemented/feature/2026-09-27-ephemeral-chat-images.md)。

## 范围

首版让新建和已有会话向 Codex、Claude 发送截图，支持文件选择、粘贴、拖拽、多图及纯图片请求。Racco 只在本轮执行期间持有图片，处理结束后释放。历史图片不提供预览或恢复，后续需要原图时由用户重新上传。

浏览器在发送前用本地 Blob 预览图片，保留图片顺序，允许移除；点击发送时将文字与图片一起提交。发送成功受理后释放本地预览，消息显示“图片 × N”。发送前失败保留草稿，未确认的断线先恢复会话再由用户决定是否重发，不自动重放。

不增加附件数据库、图片读取接口、独立上传服务、缩略图缓存、资源管理页面或历史图片重建。Provider 仍按自身规则保存原生历史；Racco 清理自己的临时数据，不修改 Provider 保存的内容，也不承诺 Provider 已删除图片。

## 发送链路

沿用 WebSocket 的 `session.create` 和 `turn.start`，将 `prompt` 替换为一次提交的有序内容块：

```ts
type UserInputPart =
  | { type: "text"; text: string }
  | {
      type: "image";
      mediaType: "image/png" | "image/jpeg" | "image/webp";
      data: string; // base64 图片内容
    };
```

输入至少包含非空文本或一张图片。服务端在分配新会话或受理本轮前完成整条输入校验；无效图片导致整条请求失败。首条创建请求的摘要包含有序文本、图片内容摘要和模型配置，继续使用现有创建身份机制。图片字节只用于本次执行，不随用户消息写入快照、事件缓存、普通日志或状态库；创建摘要不能用于还原图片。带图片的 Claude 轮次省略原始 stderr 内容，避免分段日志绕过载荷脱敏；执行错误继续返回脱敏后的原因。

| Provider | 输入方式 |
|---|---|
| Codex | Driver 将图片写入本轮私有临时目录，用 `localImage/path` 交给 App Server；文字使用原生 `text` 块 |
| Claude | Driver 将图片作为 `image/source/base64` 内容块，用只产出一条 `SDKUserMessage` 的异步迭代器交给 `query()`，继续按原生会话续聊 |

每条图片消息只上传一次；后续用户消息事件仅广播文字与图片数量。这样接受 base64 的传输开销，换取省去上传 ID、草稿附件归属和资源绑定流程。输入形式依据 [Codex App Server](https://learn.chatgpt.com/docs/app-server) 与 [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode)。

## 临时数据生命周期

Codex 临时文件归当前执行任务所有，生命周期从 Driver 准备输入到该轮执行收尾。正常完成、失败和中断都走同一清理路径；客户端断线不删除仍在执行的图片，daemon ACK 也不是删除时点。中断时先完成 Provider 停止和输入读取收尾，再删除文件。Claude 使用本轮内存中的图片内容，执行收尾后释放 Racco 持有的引用。

Codex 正常清理的触发事件是匹配当前 thread/turn 的 `turn/completed`，其状态可以是成功、失败或中断；发送 `turn/interrupt` 或收到中断请求响应都不足以触发删除。尚未向 Provider 提交就失败的准备过程可立即清理。本轮 `turn/start` 收到明确的请求或参数拒绝、尚未获得轮次 ID 且未观察到启动通知时，也清理对应批次；内部错误或传输异常不作此推断。已提交后的异常若无法确认轮次终止，保留临时文件，等待明确终态或 Provider 进程实际退出后清理；不能在任意 RPC 报错导致的 `runTurn finally` 中无条件删除。Claude 的 `result` 标记轮次完成，完成 Query 收尾后释放图片引用，本方案不为 Claude 创建图片临时文件。

临时目录位于 Linux 用户运行时目录，按 daemon 实例范围隔离，使用私有权限，不放入 Worktree 或持久状态目录。daemon 崩溃时不能依赖其清理回调：内存随进程释放，临时文件可能残留。生产环境沿用 [systemd 服务](../../systemd/raccod.service)的失败重启与整个服务 cgroup 的进程清理，先结束旧 Provider 子进程，再启动新 daemon；单实例锁本身不能证明子进程已退出。

重启后的顺序是取得当前状态目录的单实例锁、清理该实例专用的旧图片临时目录、启动新 Provider，再接收请求；无需逐张恢复归属或等待旧轮次事件。已有会话恢复逻辑将遗留的运行或等待交互状态标记为中断，读取 Provider 可用历史，但不重发图片或续跑原请求。首版不承诺恢复未完成图片输入，用户需要时重新提供图片。若服务未重启，残留文件保留到下一次安全启动清理。

普通清理失败记录错误并在后续清理中重试，不建立持久清理账本；失败的残留仍计入暂存上限。关停先等待 Provider 和当前任务结束，再完成图片清理，最后释放状态锁；清理失败也在收尾后释放锁。清理会等待已经在执行的重试，避免旧实例在释放锁后继续操作新实例目录。

图片请求的并发总字节受限，超限直接拒绝，不额外建立等待队列。临时文件删除失败占用的空间也计入暂存上限；重试清理前不得靠新目录绕过容量限制。

## 校验和界面投影

上限为每条最多 4 张、单张 5 MiB、合计 12 MiB、单张 1600 万像素，仅支持静态 PNG、JPEG、WebP。字节限制针对 base64 解码后的文件大小；WebSocket 接收消息另设 20 MiB 的解压后上限，该上限包含文字、base64 图片及 JSON 包装，文字没有另设字符数量限制。服务端验证 base64、实际格式和尺寸，并在像素展开前施加限制；完整解码限制内存、并发和时间。上游模型或代理仍可能施加更严格的限制，其拒绝按轮次错误反馈。

共享模型目录增加 `imageInput: supported | unsupported | unknown`。Codex 根据原生能力阻止向不支持图片的模型发送；Claude 未报告该能力时标为未知，由上游明确报错。服务端最终校验模型与输入，不自动删图或更换模型。

用户消息投影保留现有文字及 `imageCount`，不包含图片字节、服务器路径或可读取 URL。本轮消息按提交内容显示图片数量；历史中仍能识别图片块时显示“图片 × N · 未保留预览”，纯图片消息保留其位置。原生历史没有提供的信息不额外持久化或猜测补齐；即使有内嵌图片也不解码提取，不为历史回显新增缓存或接口。

协议、两家 Driver、首页与会话输入框、消息展示、轮次摘要及 fixture 一次更新，不保留旧协议分支。不新增图片表或图片元数据列。创建摘要格式随内容块协议更新，状态版本为 9，按项目规则直接拒绝旧版本，不做迁移。

## 验证

运行 `npm run check` 检查协议、服务端、输入框与浏览器行为。图片专项覆盖格式与大小拒绝、模型能力门禁、字节不进入快照、提交失败保留草稿、纯图片占位、移动端交互、终态、明确请求拒绝的清理及不确定异常的安全保留、启动残留清理与状态目录软链接别名。

`npm run smoke:images` 用隔离的项目和状态目录验证两家真实 Provider：图文、多图、纯图片、临时文件清理、文字续聊、历史占位，以及重启后的普通续聊。可用 `RACCO_CODEX_MODEL`、`RACCO_CLAUDE_MODEL` 从各自目录中选择实际支持图片的模型。脚本只删除自己创建的原生会话，不重启用户正在运行的 daemon。

当前接入的 Claude 单消息输入流在 `result` 后结束迭代，Driver 继续消费到结束以保留尾部事件。Codex 清理临时文件后，原生普通续聊与重启后的续聊可继续执行；历史图片预览仍不作为产品能力。Provider 接入发生变化时应重跑这项验证，不能通过恢复永久附件存储掩盖生命周期问题。
