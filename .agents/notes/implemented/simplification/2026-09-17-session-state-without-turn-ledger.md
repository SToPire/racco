# Agent Note: 会话管理不保留逐轮执行记录

Status: implemented

## Problem

Racco 已从 Provider 读取消息与原生 turn 历史，额外保存逐轮执行记录使普通消息和压缩都承担数据库生命周期、去重与恢复成本。项目当前不需要逐轮审计或跨重启请求重放保证，压缩也只是一次原生操作。

## Decision

删除 Racco 的 turns 表及逐轮请求摘要、参数和状态存储，不用内存历史列表或另一张表替代。数据库只保留项目与会话，包括当前会话状态和最近模型偏好；普通生成仅管理当前运行的任务及交互。压缩直接调用原生 API，不创建持久化执行记录或停止／恢复流程；其界面忙碌标记由[压缩忙碌反馈](../feature/2026-09-17-compaction-busy-feedback.md)限定为当前操作的运行时状态，替代此前仅等待请求响应的交互。上下文读数通过独立 Provider 通知更新，只缓存在 daemon 内存中。

客户端断线后不自动重发未确认命令，保留草稿并提示用户先查看恢复的会话。创建请求身份继续由会话行保存，避免重复创建原生会话；这不扩展为逐轮记录。此决策部分替代[模型选择](../feature/2026-09-17-composer-model-selector.md)的逐轮持久化与重放要求，以及[上下文控件](../feature/2026-09-17-codex-context-controls.md)的压缩状态和用量持久化要求；两个功能记录保留其界面、配置和指标语义。

会话可用性与错误详情的进一步收窄由[即时错误反馈](2026-09-19-session-errors-are-transient.md)规定，当前执行状态与创建幂等仍然保留。

## Alternatives considered

**保留 turns 表：** 原方案服务于请求去重、并发约束、异常恢复及每轮配置记录，但这些保证不足以抵偿当前项目的复杂度；只有出现明确的持久任务或审计需求时才重新评估。

**改为另一张操作表或累计内存请求清单：** 仍保留逐轮登记的负担，没有实现简化目标。

**移除记录但继续自动重放：** 无法判断断线前的请求是否已执行，可能重复提交任务；因此同步去掉自动重放。

## Consequences

Provider 是对话历史的事实来源；Racco 的持久化规模随项目与会话数量增长。普通消息仍有运行时并发检查，会话残留运行状态在启动时标记中断，但不承诺逐轮审计、请求恰好执行一次或自动补发。压缩完成和失败由后续 Provider 通知呈现，RPC 成功仅表示请求被接受。浏览器刷新和重连共享内存读数，daemon 重启后需等待新的用量报告。旧 schema 按项目规则直接拒绝，不增加迁移或兼容分支；生产 schema 与执行路径只保留项目和会话存储，测试明确校验没有逐轮表和上下文读数列。
