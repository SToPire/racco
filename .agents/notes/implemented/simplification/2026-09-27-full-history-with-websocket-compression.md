# Agent Note: 完整历史读取与 WebSocket 压缩

Status: implemented

## Problem

长会话的完整历史及子任务内容增加手机首屏的传输、解析和渲染工作。已有 HTTP 压缩不覆盖承载首屏快照的 WebSocket；在尚未测定压缩后的瓶颈前，同时引入历史分页会增加游标、实时合并和阅读位置维护成本，也难以判断单独压缩的收益。

## Decision

会话订阅恢复完整历史快照及子任务内容，后续继续接收实时更新；WebSocket 独立启用消息压缩，小于 1 KiB 的消息跳过压缩，禁用跨消息字典复用。选择先减少传输字节数，再依据实测决定是否需要限制首屏历史量。历史仍归 Provider 所有，不新增持久化副本、轮次索引或数据库字段。

本记录完整整合并替代[会话历史从尾部按需分页](https://github.com/SToPire/racco/blob/68485c9125031b16277c3af02abbd8668fc79e59/.agents/notes/implemented/feature/2026-09-26-history-pagination.md)，删除其现行记录。[会话切换缓存](../bug-fix/2026-09-22-session-switching.md)恢复完整快照的刷新方式；[子任务流式基线](../bug-fix/2026-09-22-codex-background-child-events.md)继续约束读取与实时增量交错时的恢复，[原生历史归属](2026-09-17-session-state-without-turn-ledger.md)继续持有存储边界。

## Alternatives considered

**保留按需分页：** 最近轮次和选中子任务才传输，可减少首屏处理量；但 Codex 需要原生分页能力，Claude 仍需完整冷读取与内存历史。即使 Claude 按请求扫描而不保存索引，也要维护游标有效性、旧页与实时内容合并、刷新语义及滚动锚点。当前缺少压缩不足以改善体验的证据，因此撤销分页。

**增加历史缓存或索引：** 服务端持久化副本增加同步成本，浏览器持久缓存无法改善首次访问，Claude 轮次索引增加状态维护；这些方案都不作为本次传输优化的前提。

## Consequences

会话历史的分页接口、游标协议、前端入口和对应支持测试全部移除，放弃只加载最近轮次及按需读取子任务的能力。完整读取继续保留消息和工具输出；Claude 外部修改按既有订阅读取规则校准，无需分页专用刷新。会话切换与阅读位置由[浏览器测试](../../../../test/e2e/session-switching.spec.ts)约束，子任务恢复由[续流测试](../../../../src/server/drivers/codex/snapshot-stream.test.ts)约束。

压缩以计算成本换取更少传输字节，禁用跨消息字典复用以限制每个连接保留的压缩历史；完整历史的读取、内存、JSON 解析和渲染成本仍然存在，大段工具输出不会被截断。只有实测表明压缩后仍因历史规模而阻塞首屏，才重新评估分页或渲染优化；届时仍需验证实时合并、子任务恢复及移动端阅读位置，不能仅凭传输体积判断体验。
