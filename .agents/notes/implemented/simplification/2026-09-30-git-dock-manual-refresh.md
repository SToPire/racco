# Agent Note: Git Dock 由用户导航和手动操作刷新

Status: implemented

## Problem

Git 修改的持续轮询及浏览器焦点恢复刷新增加了用户没有要求的 Git 扫描，查看内容也可能在阅读中自动变化。新增第三个 Dock 入口后，手机端紧凑按钮容器容不下三个固定尺寸按钮；没有选中文件时的详情引导文字又占用额外视觉空间。

## Decision

Git 列表仅在用户进入面板、切换 Worktree 或点击刷新时读取一次，不保留定时器、自动重试或焦点／可见性恢复读取。文件选择仅按需读取该项差异；列表读取期间的显式文件选择等待该次列表尝试结束再执行，不因列表失败而丢掉，也不在切离面板后重放。成功的手动或导航刷新同步重读选中详情。暂态失败保留上次结果并明确提示过期，确定失效清除对应内容；取消读取不能留下阻止用户重试的忙碌标记。

手机端的紧凑 Dock 入口在原有容器内部横向滚动，按钮保持可点击尺寸，不将内容挤出屏幕；未选中文件时差异区域留空，已有加载和错误反馈仍由实际读取状态驱动。本决策部分替代[当前 Git 修改 Dock](../feature/2026-09-30-git-changes-dock.md)的周期刷新选择，保留其 Git 基线、只读查看、安全边界和隔离测试部署决定；[Worktree 管理](../architecture/2026-09-20-git-worktree-management.md)的目录清单显式刷新规则继续有效。局部检查没有完全被替代或需要归档的记录。

## Alternatives considered

**保留可见面板轮询及焦点刷新：** 更新更及时，但增加扫描和非用户发起的界面变化，不符合当前按需查看的要求。

**扩大紧凑按钮容器或缩小按钮：** 前者增加与手机顶部其他控件的竞争，后者降低点击可靠性；内部滚动保留布局和按钮尺寸。

**继续显示未选择的详情引导：** 能解释下一步操作，但文件列表已提供入口，额外文字对当前查看流程没有必要。

## Consequences

Git 修改不再自动跟踪外部编辑，用户通过明确导航或刷新取得新快照；文件差异仍为用户选择时的当前读取结果，不承诺轮次归因或原子快照。紧凑入口的末尾按钮可能需要横向滑动或键盘聚焦才能露出；三个面板的既有导航与收起职责不变。
