# Agent Note: 按行为边界选择测试夹具

Status: implemented

## Problem

每个浏览器用例创建完整 Git 历史增加重复准备成本，而原生协议测试中的宽松应答和固定延迟会掩盖未知 RPC 并使消息顺序依赖调度。

## Decision

需要仓库、删除或文件边界的浏览器测试继续创建真实 Git 项目；纯呈现测试显式选择位于独立临时目录的轻量项目夹具。Codex 协议测试共用真实 stdio 子进程安装器，逐项声明 RPC handler，未知方法返回协议错误；完成通知通过应答前或应答后握手调度，不通过短延迟猜测时序。损坏输出、EPIPE、锁和删除测试仍使用对应真实系统边界。本记录与[手动执行项目检查](../process/2026-09-19-manual-project-checks.md)分别持有夹具边界和门禁触发方式；局部审查未发现需要取代的现有夹具决策。

## Alternatives considered

把所有用例迁移到共享持久服务器会降低隔离性；把原生管道完全 mock 掉会遗漏进程退出和传输失败；只增加超时不能保证事件先后关系。

## Consequences

轻量夹具不可用于声称验证 Git 行为的测试，协议新增方法必须显式更新受影响的 handler。呈现测试仍验证真实 HTTP、WebSocket 和浏览器渲染，夹具选择与行为覆盖由用例共同表达。
