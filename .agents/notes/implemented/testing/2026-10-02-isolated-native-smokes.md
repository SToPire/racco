# Agent Note: 原生冒烟测试拥有独立运行目录

Status: implemented

## Problem

模型与交互冒烟默认连接日常 daemon，并把当前工作目录及临时对话写入真实工作空间；失败后只断开 WebSocket 无法清理这些副作用。

## Decision

默认模型与权限冒烟构建并启动编译产物，拥有临时配置、项目、数据库和进程组，结束时删除该项目路径下本次产生的原生会话并等待进程退出后清理目录。必须同时显式提供目标 URL 与项目路径才进入由调用者负责清理的诊断模式；脚本不再隐式连接日常 daemon。冷续接冒烟自己创建首轮记忆、停止并重启隔离进程，第二轮不重述记忆值；同时核对原生 ID、历史顺序、内容及消息身份，事件条数不再充当持久化证明。真实模型冒烟保持手动入口，不进入常规检查；无模型的严格原生协议替身验证编译产物的重启路径。本记录经同机制局部审查，与[夹具边界](2026-10-02-fixture-boundaries.md)互补，保留其模拟协议与真实系统边界要求。

## Alternatives considered

在现有 daemon 中自动导入再删除项目无法隔离并发用户操作和意外失败；启动源码服务器不能证明用于烟测的编译入口与产物可执行；复制用户的整套配置及历史会增加隔离范围和秘密文件处理成本。

## Consequences

原生 CLI 继续使用已配置的凭据与安装，但项目和 Racco 状态属于本次运行。清理失败会明确失败而非打印成功；[原生烟测说明](../../../../docs/testing/native-smokes.md)持有执行方式与验证范围。真实模型调用有成本，维护者需要主动执行。诊断模式明确保留目标服务和会话，不承诺自动回滚。
