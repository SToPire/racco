# Agent Note: Codex 子任务事件独立于主轮次寿命

Status: implemented

## Problem

Codex 子任务可以在主 Agent 已回复后继续运行，但事件转发依赖主轮次的临时上下文。主轮次结束后，子任务输出、完成和中断事件被丢弃，任务卡与工具行因此停留在运行中。

## Decision

Codex 驱动按原生父子关系把子任务事件路由到所属会话：主轮次活跃时沿当前时间线发送，主轮次结束后通过会话更新继续发送。已知会话下后来启动的嵌套子任务使用同一归属；子任务不会占用主轮次发送入口，也不因主轮次结束而被推断为完成或停止。子任务终态以其原生通知为准，Provider 退出时明确终止仍未完成的观测，保留已结束任务的结果。

首次接续运行中的子任务时，快照中的日志、正文、方案和公开摘要作为后续增量的内容基线。缺少基线的增量保护从识别出子任务时开始，不能仅覆盖某次读取期间；真实开始事件提供完整基线后可以立即续流。快照本身不能证明某个文本块仍在生成，因此不把已恢复正文登记为待完成消息；只有实际增量或开始事件激活续流。较新快照可以推进尚未续流的基线，已观测到的增量和终态不能被迟到快照回退；这些约束补全[Codex 展示性过程](../feature/2026-09-22-codex-visible-activity.md)的实时与历史衔接，不扩展公开内容范围。

本决策补充[子任务摘要](../feature/2026-09-22-subagent-task-summaries.md)和[工具终态](../feature/2026-09-22-tool-lifecycle-states.md)的后台事件可达性，两者的展示与状态含义保持有效；没有需要完整替代的记录。[原生历史归属](../simplification/2026-09-17-session-state-without-turn-ledger.md)继续有效，归属与未完成调用仅在驱动内存中跟踪，不建立持久执行账本。

## Alternatives considered

**让主轮次一直等待全部子任务结束：** 可复用临时上下文，但会阻塞主对话下一轮，把后台执行错误变成主轮次完成条件。

**主轮次结束时关闭子任务或推断其成功：** 使界面状态看似完整，却改变原生执行行为或伪造尚未报告的结果。

**只在用户重开对话时重读历史：** 能恢复最终结果，但运行中的用户仍看不到实时进展，无法满足后台任务的可观察性。

**把快照一律当作运行中消息或通过字符串重叠猜测去重：** 前者会在结束时重复提交已完成文本，后者无法可靠判断一次增量是否已包含在快照中。基线与实际续流分开，无法确定先后关系时明确报告同步失败。

## Consequences

同一会话的子任务可以跨主轮次继续更新，重读历史保留当前驱动内的 Agent 标识，后续事件仍落到同一子对话。子任务不修改主轮次状态，Provider 退出与会话删除清理相关归属和未完成缓存。跨轮、重读和退出行为由[后台事件测试](../../../../src/server/drivers/codex/background-events.test.ts)约束；这项改动只恢复事件投递，不为后台任务新增独立用户交互或控制入口。

原生增量没有可用于快照对齐的位置或序号。首次读取若遇到缺少基线的增量，最多额外读取一次；持续交错时本次读取明确失败，用户需要重试，不能无限等待或显示仅剩后缀的内容。明显早于已观测工具或轮次终态的快照同样被拒绝，避免重新显示运行中。新的完整项或后续成功快照可以解除未对齐状态，终态与关闭会清理它；已建立基线的正常续流不增加读取次数。快照推进、逆序响应、终态保护及有界恢复由[续流测试](../../../../src/server/drivers/codex/snapshot-stream.test.ts)约束。

会话层读取历史期间若收到实时更新，继续保留实时内容，同时明确提示本次未更新完整历史，不能把未安装的恢复快照静默当作成功。后续没有竞争的重读恢复完整历史；提示只属于该次读取响应，不写入会话历史。这一边界同样适用于已有主对话中首次出现的子任务，不以主对话是否曾加载成功代替子任务完整性判断。
