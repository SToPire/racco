# Agent Note: 工具折叠保持时间线顺序

Status: implemented

## Problem

工具组把较早的成功调用收集到顶部历史区，同时将失败、运行及选中项留在外部，破坏原始顺序。失败 A 先于成功 B、C、D 时，展开后变成 B、A、C、D；选择 B 又恢复 A、B、C、D，用户正在阅读的调用因此跳位。

## Decision

工具组按已有时间线顺序划分连续历史前缀与近期后缀：三条以内全部显示，超过三条时最后两条常显，其余统一折叠。状态和选中项不参与划分；展开、选择和状态更新保持调用顺序及所属区域。历史标题使用“较早”并按工具原名计数，不把历史调用统称为已完成。[显式轨迹定位](../feature/2026-09-22-trajectory-location.md)展开目标所在历史区后滚动到调用，保持其历史归属。

本决策部分替代[工具活动摘要](../feature/2026-09-22-tool-activity-summaries.md)的默认可见性规则，并更新[可理解执行过程](../feature/2026-09-22-chat-observable-work.md)的相关总览。动作摘要、紧凑布局和按需详情仍由原记录持有；[工具原名](../simplification/2026-09-22-original-tool-names.md)与[生命周期状态](../feature/2026-09-22-tool-lifecycle-states.md)的语义继续有效，没有需要完整替代的记录。

## Alternatives considered

**继续按状态和选择保留常显项：** 能突出异常和当前关注项，但把非连续历史移到顶部会改变顺序，选择与状态更新还会让调用换位。

**按成功调用分段折叠：** 可避免跨失败项收集历史，却仍让状态决定折叠边界，状态变化会改变分段，不符合统一折叠连续历史前缀的要求。

## Consequences

展开后的调用顺序与时间线一致，较早的失败、运行及选中调用也可能隐藏，需要展开历史查看；折叠摘要因此不能承诺调用已完成。后续新增调用会按时间推进历史边界，既有调用的相对顺序保持不变。[组件测试](../../../../src/web/components/ToolGroup.test.tsx)与[浏览器回归](../../../../test/e2e/chat-activity.spec.ts)约束分组边界、选择和状态变化时的顺序稳定。
