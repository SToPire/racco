# Agent Note: 目录刷新与实时事件的一致归并

Status: implemented

## Problem

首页和重连的 REST 目录读取可能晚于 WebSocket 创建、更新或删除事件完成。直接替换列表会恢复已删除对象、丢失新会话并清空有效显示缓存；交叠刷新也可能让旧结果覆盖新结果。

## Decision

项目、会话和 Worktree 目录由同一个 reducer 维护。REST 读取提供基线，读取期间观察到的实时和本地操作按顺序重放；只有当前读取代次可以提交结果。单项目 Worktree 读取使用同样规则；新的全局刷新替代之前未完成的单项目读取，之后发起的单项目读取仍可更新基线。项目删除统一移除其会话、Worktree 和错误，显示缓存只按归并后的会话目录清理。

本记录补充[会话切换](2026-09-22-session-switching.md)的重连核对，并保留其显示缓存、Provider 历史归属与不自动重放命令的决策；[Worktree 管理](../architecture/2026-09-20-git-worktree-management.md)继续持有目录归属。同范围没有完整替代的记录。

## Alternatives considered

**各组件独立替换 REST 结果：** 实现局部简单，却不能保留读取期间已经接收的更新，且删除关系需要多处重复维护。

**只靠取消旧 fetch：** 可减少无用读取，但取消与响应交错不能保证状态一致，也不解决同一次读取与实时事件的顺序问题。

## Consequences

读取期间短暂保存目录事件，完成或失败后释放；不保存历史执行账本。重连仍从服务端获取目录基线，事件优先级只覆盖同次读取窗口内客户端实际观察到的变化。
