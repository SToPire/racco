# Agent Note: WebSocket 活性与命令结果期限

Status: implemented

## Problem

浏览器 WebSocket 可能在网络黑洞中持续显示连接，既没有关闭事件，也收不到命令确认。输入界面会永久等待，用户无法分辨命令尚未执行还是确认丢失。

## Decision

连接通过有期限的应用层心跳确认双向通信；每条业务请求也有独立结果期限。任一期限到达立即使当前连接失效、释放等待状态并启动重连，不依赖浏览器完成关闭握手。尚无确认的请求被明确报告为结果未知，重连后重新读取目录与当前会话，用户核对状态后决定是否重试，客户端从不自动重放业务命令。

本记录补充[会话切换](2026-09-22-session-switching.md)的重连责任与[命令结果接口](../simplification/2026-10-02-current-command-results.md)的确认语义；两者继续保留显示缓存和单一命令结果路径的理由，没有完整替代的记录。

## Alternatives considered

**仅监听浏览器关闭事件：** 无法发现不产生关闭事件的连接，无法给等待中的用户一个有界结果。

**超时自动重试：** 无确认不等于未执行，重放创建或发送命令可能导致重复会话和重复任务；结果未知需要重新读取后由用户判断。

## Consequences

空闲连接产生少量心跳流量；繁忙或长时间后台挂起的页面可能重新连接，但不会因此重复执行任务。响应超时只是客户端的观察期限，不会取消服务端已经开始的工作。
