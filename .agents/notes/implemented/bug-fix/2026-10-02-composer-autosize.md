# Agent Note: 消息输入随内容增高并限制占用

Status: implemented

## Problem

已有会话输入固定为一行且禁止拖动，多段任务只能在很小的内部滚动区域编辑。首页依赖手动拉高，手机上不能获得一致的编辑空间。

## Decision

首页与会话输入随内容自动增高，沿用各自的最小和最大高度；超过上限时在文本框内部滚动，清空或发送后收回。可用宽度变化或缓存视图重新显示时重新测量，使换行后的可见空间与内容一致。

此修复细化[首页输入页](../simplification/2026-09-18-home-composer.md)与[连续会话控制](../feature/2026-09-22-continuous-session-controls.md)的编辑体验；Enter、Shift+Enter、输入法与禁用状态保持原有语义。[草稿生命周期](2026-10-02-draft-lifetime.md)继续持有输入归属，没有需要完整替代或归档的记录。

## Alternatives considered

**固定多行高度：** 能多显示一些文字，但短消息常态也占据更多聊天空间，长任务仍缺少自适应能力。

**只允许用户拖动输入框：** 桌面可用，手机不便；自动测量内容同时覆盖两处输入区和窗口宽度变化。

## Consequences

用户可直接检查多段任务，代价是长草稿占用更多会话高度，因此必须保留高度上限和内部滚动。尺寸观察只在宽度变化时重算，避免高度调整触发自我循环；浏览器验证应覆盖增长、清空、窄屏换行及隐藏视图恢复。
