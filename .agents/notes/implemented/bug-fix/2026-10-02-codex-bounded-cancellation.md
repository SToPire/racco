# Agent Note: Codex 停止等待必须有界

Status: implemented

## Problem

原生轮次已经开始但启动回执未到时，Racco 还不能确认本轮身份，停止操作无法发出对应中断。中断请求成功也不等于执行已停止；一直等待丢失的确认会使任务永久占用会话。

## Decision

停止请求从执行准备阶段起进入有界等待。已有可信轮次身份时发送一次原生中断，只有对应终态结束等待；启动回执稍后到达仍可完成正常中断。无法在期限内确认停止，或原生中断请求失败时，关闭整个 Codex Provider；所有受该共享故障影响的轮次都等待原生进程退出，再释放各自的执行占用，不能仅等待发起取消的那一轮。界面明确提示同一 Provider 的其他会话也会受到影响。

早到通知可能属于前一次压缩，不能用于猜测本轮身份；变更结果不确定时不重发启动，也不把中断 RPC 成功当作终态。本记录补充[问答与中断](../simplification/2026-09-19-question-only-interactions.md)的确认边界，沿用[传输故障隔离](2026-10-02-codex-transport-failure-isolation.md)和[无逐轮记录](../simplification/2026-09-17-session-state-without-turn-ledger.md)的故障与不重放决定，没有被完整替代的记录。

## Alternatives considered

**直接解除本地忙碌状态：** 原生任务仍可能修改文件，会让后续操作与未停止的任务重叠。

**根据任意早到通知发送中断，或重试启动：** 可能打断旧轮次或重复执行变更，无法保证操作对应用户当前的停止请求。

**永远等待原生确认：** 不影响其他会话，但失去停止能力。保留短暂正常收尾机会，随后牺牲该 Provider 的可用性以结束不确定执行。

## Consequences

正常中断不关闭 Provider；异常取消会结束共享进程中的 Codex 会话，其他 Provider 继续运行。关闭进程不能撤销已经发生的外部副作用，不承诺终止原生进程之外的独立后台服务。临时图片仍按[已确认终态或进程退出](../feature/2026-09-27-ephemeral-chat-images.md)清理。[真实子进程测试](../../../../src/server/drivers/codex/cancellation.test.ts)约束丢失启动回执、缺失中断终态、迟到回执、旧终态干扰和不重放行为。
