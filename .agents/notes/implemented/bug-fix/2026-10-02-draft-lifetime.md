# Agent Note: 未发送草稿独立于会话视图缓存

Status: implemented

## Problem

新建页进入已有会话会卸载输入区，最近会话的显示缓存也会淘汰旧视图。把未发送文字与图片放在组件内，会让普通导航静默丢弃用户尚未提交的工作。

## Decision

当前页面独立持有未发送草稿，视图仅订阅对应输入。已有会话按会话身份隔离；首页文字延续切换项目时可携带的行为，首页图片按项目和工作目录隔离，切回原目录仍可恢复。图片读取的所有权同样属于草稿，离开视图不取消尚未完成的准备。

明确受理发送后清空对应草稿，移除图片、删除所属会话或项目以及关闭页面时释放本地预览。文字和图片均不写入浏览器持久存储，不增加自动重发、历史附件或跨设备草稿能力；[临时图片](../feature/2026-09-27-ephemeral-chat-images.md)的服务端生命周期保持不变。

本记录部分替代[会话切换](2026-09-22-session-switching.md)中草稿跟随显示缓存淘汰的边界，并扩展[首页输入页](../simplification/2026-09-18-home-composer.md)的页面内保留范围；原记录继续约束有界 DOM、阅读位置和浏览器历史。[跨视图操作](../feature/2026-09-22-continuous-session-controls.md)的未确认发送锁定与无队列语义仍有效，没有需要完整替代或归档的记录。

## Alternatives considered

**继续保留更多会话视图：** 只能延后草稿损失，还会把大量历史 DOM 留在内存中；草稿大小和历史大小应独立管理。

**将图片与草稿写入本地存储或服务端：** 能恢复刷新与跨设备状态，但增加敏感图片留存、存储预算和清理契约，超出当前页面内导航需求。

## Consequences

页面内导航和显示缓存淘汰不再丢弃未发送输入。代价是页面会保留用户尚未提交的草稿及图片内存，直到发送、删除或离开页面；现有每条消息图片数量和字节限制仍适用。回归应验证真正逐出视图后的恢复、项目图片隔离及资源释放，而不只覆盖两个持续挂载视图之间的切换。
