# Agent Note: 切换会话复用视图并恢复阅读位置

Status: implemented

## Problem

跨项目切换会话时清空消息、等待完整历史并重建视图，会把 Provider 读取、时间线重建和 Markdown 渲染的成本反复放在导航路径上。组件销毁也丢失阅读位置与草稿，长对话因此既卡顿又回到顶部。

## Decision

浏览器保留最近访问会话的有界显示缓存及其视图，切回时立即复用，再通过订阅取得最近历史页。阅读位置、输入草稿与所选视图随缓存保留；首次打开显示最新内容，已向上阅读的用户不因后台刷新被拉回底部，停留在底部的用户继续跟随新输出。缓存只服务展示，不写入数据库或浏览器持久存储，移除会话或项目时一并丢弃。

历史页按事件标识构建显示行，避免逐条复制和扫描已增长的历史；未变化的 Markdown 与时间线复用渲染结果。快速导航以最后一次订阅为准，迟到的历史读取不能抢走新会话的流式订阅。返回项目列表复用已有目录数据，重连时重新核对目录并取得最近历史页。历史加载范围与 Claude 外部修改的刷新方式由[按需分页](../feature/2026-09-26-history-pagination.md)部分替代，已加载旧页在边界可对齐时继续复用。

本记录补充[Worktree 管理](../architecture/2026-09-20-git-worktree-management.md)的导航行为，以及[首页输入页](../simplification/2026-09-18-home-composer.md)的页面内草稿保留；两者继续持有工作目录归属和浏览器历史语义。[无逐轮记录](../simplification/2026-09-17-session-state-without-turn-ledger.md)继续有效：显示缓存不是执行账本，Provider 仍是历史的事实来源，不新增自动命令重放。同范围没有需要完整替代或归档的记录。

## Alternatives considered

**每次切换都重新加载并重建视图：** 状态少，但外部读取延迟和历史渲染持续阻塞重复导航，且阅读位置与草稿随组件销毁丢失。

**无限保留全部访问过的视图：** 返回任何会话都方便，但长历史的 DOM 和内容会无界增长。采用最近访问淘汰，限制同时保留的视图。

**只使用缓存、不再向 Provider 校验：** 能省去读取，但会漏掉原生客户端修改和离开期间的事件，因此切回仍重新订阅以恢复实时流；历史校准按当前分页决策执行，Claude 外部修改需显式刷新。

## Consequences

最近访问的会话可在网络刷新完成前恢复阅读和编辑；代价是保留有限数量的消息与 DOM。超过缓存上限、页面刷新或关闭后需要重新读取，阅读位置与草稿不承诺跨这些边界保存。无可用服务端历史时首次读取仍依赖 Provider；缓存不能用于跳过服务端发送、删除和交互有效性检查。回归测试需要覆盖慢刷新、快速交错订阅、旧内容更新、滚动跟随和缓存清理，而不只检查静态页面结构。
