# Agent Note: WebUI 状态与阅读呈现保持一致

Status: implemented

## Problem

同一会话在历史列表、Agent 选择器和顶栏使用不同的状态文案与颜色，小字号和彩色文字在明暗主题中的可读性也不一致。消息列与输入框各自计算留白，使内容边界随面板宽度改变；仅处理 CSS 动画无法满足用户减少动效的偏好。

## Decision

文字输入与搜索继承全局键盘焦点轮廓，局部外观样式不能清除轮廓而不提供等价提示；已有容器焦点提示的目录输入保持其独立边界。焦点以形状和颜色共同呈现，不依赖占位文字或光标位置。

主会话使用一份穷尽状态文案，子 Agent 复用共有状态的文案并保留其独有状态；二者共用状态配色。可见文字或控件的可访问名称承载状态含义，颜色提供辅助线索。连接状态、主会话和所选子任务继续独立呈现，连接异常提供文字（窄屏顶栏仅显示圆点，文字保留在可访问名称中）；主动中断使用提醒色，不等同于执行失败。窄屏顶栏的状态保持与标题同行，空间不足时标题缩略截断，状态不独占一行；Agent 选择器被挤压时裁切自身内容，不覆盖状态。普通状态与 Provider 标签文字在明暗主题均满足 4.5:1 的对比度目标，头像背景与图标前景同步适配主题，轨迹类别使用独立于 Provider 品牌的呈现语义。

阅读文字使用少量 rem 字号档位，紧凑元信息以默认根字号下的 11px 为下限；文件类型的字母图标保留更小的符号尺度。普通、次要和辅助文字保留层级，同时保证选中背景上的可读性。这是信息密度与中文可读性的产品取舍，不是无障碍标准规定的最小字号。轨迹工具栏在窄面板或字体放大时按内容换行，指标的数值与名称保持完整，搜索框宽度随字号调整并受面板边界约束，不靠裁切或缩小文字维持单行。消息正文保留相对标题层级，图片数量继续使用轻量占位，禁用发送按钮保留原生禁用语义。

Chat 的可见消息列与输入框共享宽度、居中和水平留白，并计入滚动条占位。系统要求减少动效时，CSS 动画、过渡与显式轮次平滑滚动均停止，导航目的地与阅读归属保持不变。

本决策细化[正文居中](2026-09-28-subagent-topology-centering.md)的内容边界，保留悬浮拓扑不挤压正文的约束；[阅读位置](../feature/2026-09-22-conversation-reading-position.md)与[轨迹定位](../feature/2026-09-22-trajectory-location.md)继续持有跟随和导航语义。[临时图片](../feature/2026-09-27-ephemeral-chat-images.md)的数量占位与存储边界不变，无需完整替代或归档相关记录。

页面外壳列宽与布局容器由 base.css 统一拥有；跨组件视口、容器断点集中于最后加载的 responsive.css，组件文件保留局部外观。侧栏、Dock 和拓扑几何尺寸使用公共 CSS token，拓扑的空间判断读取同一 token，避免样式与行为重复维护数值。断点维持现有响应式语义，不引入额外样式框架。

## Alternatives considered

**把所有状态合成一个指示器：** 能减少视觉元素，却会混淆连接中断、主任务执行和子任务完成，失去独立的操作依据。

**只改局部颜色、字号或宽度常量：** 修改范围较小，但仍会留下多份文案、不同内容盒和暗色主题遗漏；统一呈现规则减少再次漂移的入口。

## Consequences

状态更易辨认，窄面板和长对话中的消息边界保持稳定，用户的动效偏好同时约束样式与程序化滚动。较大的元信息可能更早截断长名称，因此后续改动仍需验证窄屏与字体放大下的操作可达性；极端窄屏与放大字号下 Agent 选择器的名称与箭头会被裁切，仅保留状态圆点与下拉按钮入口；窄屏连接状态对弱视用户仅以色相区分，文字仍保留在状态区域的播报内容中。滚动条占位测量不能通过裁切输入框菜单来替代。[浏览器回归](../../../../test/e2e/web-presentation.spec.ts)覆盖状态一致性、主题对比度、内容边界与动效偏好。
