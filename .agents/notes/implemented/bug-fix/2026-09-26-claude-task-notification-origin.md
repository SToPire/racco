# Agent Note: Claude 任务通知不计为用户发言

Status: implemented

## Problem

Claude 的 user 角色也承载后台任务通知，不能直接代表真人输入。SDK 历史消息投影省略来源字段，使任务完成通知在重新读取会话后被显示为用户消息，并增加对话导航中的轮次数。

## Decision

[历史读取](../../../../src/server/drivers/claude/history.ts)保留 SDK 对主会话和子会话的分支、压缩选择，只按已选消息的 UUID 恢复原生 origin。[事件映射](../../../../src/server/drivers/claude/event-mapper.ts)在历史和实时路径共同排除没有 subkind 的 task-notification 来源用户文本，工具结果继续独立处理。带 subkind 的定时任务或转发输入继续显示，不能把这些消息与通用后台通知混为一类。缺少来源的消息维持普通文本展示；正文包含通知标签并不改变其来源。此规则仅作用于展示，不修改原生会话或恢复执行所用的上下文。

本决策补充[结构化工具结果](2026-09-22-claude-structured-tool-results.md)的原生元数据恢复边界，以及[任务原生归属](../feature/2026-09-22-claude-task-ownership.md)的用户发言分类。两者继续拥有结果和任务生命周期语义，没有完整替代或归档项。

## Alternatives considered

**由前端过滤通知标签：** 无法区分真正的任务通知与用户粘贴的示例，也让服务端快照继续错误声明用户发言。

**在 SDK 选择前删除通知记录：** 通知可能是后续回复的父节点，提前删除会干扰原生历史结构。先完成选择，再决定显示事件。

**只保留显式 human 来源：** 当前真人输入也可能没有 origin，严格要求该字段会隐藏有效消息。缺失来源不补造，也不等同于任务通知。

## Consequences

任务通知不再占用用户轮次，子任务对话和工具结果仍可阅读。该分类依赖 Provider 提供结构化来源；来源缺失时不能仅凭正文判定通知。新增来源分类需要明确其展示语义，不能把 user 角色统一解释为真人作者。
