# Agent Note: 停机发布完整生产构建

Status: implemented

## Problem

运行中的服务端已载入旧代码，但静态资源仍按构建目录读取；直接替换该目录会让旧后端服务新前端。

## Decision

生产构建在当前检出正由 systemd 用户服务运行时，先停止服务，再构建和替换完整产物，最后启动并确认运行中的构建标识。前一构建保留到新实例就绪；编译或启动失败则恢复旧产物并重启旧实例。其他检出的服务不受影响，验证构建仍写隔离目录。

## Alternatives considered

**不可变发布代与无停机切换：** 可以缩短中断，但需要额外进程路由与旧资源保留政策；当前单用户桌面服务接受一次明确重启。

## Consequences

更新期间会话连接中断，用户应等待服务恢复并刷新旧页面；旧的内容 hash 资源不承诺跨发布保留。构建失败恢复仅覆盖产物，不回滚独立执行的依赖安装、配置或数据库变更。恢复也失败时保留备份并报告位置。真实临时服务的[发布回归](../../../../scripts/deploy-build.test.mjs)验证停止顺序、前后端代号与失败恢复，测试不操作用户服务。
