# Agent Note: 工具终态与进度保留已知事实

Status: implemented

## Problem

工具调用只区分成功与失败，无法表达中断或缺失结果；会话结束时未收到完成事件的工具仍可能显示运行中。用户因此不能判断调用是否停止，原生已提供的进度也无处展示。

## Decision

共享工具契约明确区分完成、失败、中断和结果未知，并保留 Provider 报告的耗时进度。Codex 在查询期间跟踪尚未结束的调用：原生轮次中断或失败时收束对应工具，Provider 退出时终止仍等待结果的调用；正常轮次结束却没有工具终态时标为结果未知，不推断成功。原生历史采用相同规则，保留已收到输出，不补造退出码、最终耗时或完成结果。

本决策补充[工具活动摘要](2026-09-22-tool-activity-summaries.md)的状态真实性，并与[Codex 展示性过程](2026-09-22-codex-visible-activity.md)共享终止语义；两者继续持有各自的摘要和内容投影决定。相关记录没有被完整替代。[无逐轮记录](../simplification/2026-09-17-session-state-without-turn-ledger.md)仍约束历史归属，新增跟踪仅服务于未结束调用，结束即清除。

## Alternatives considered

**仅依据会话状态修改视觉标签：** 无法保留单个调用先前完成或失败的事实，实时与重读历史也会产生差异。

**将所有未结束工具判为失败或随轮次成功判为完成：** 缺少工具结果不能证明执行成功，也不能等同于原生报告的失败；结果未知保持这一信息边界。

**从前端时间或后台任务状态延伸调用进度：** 会编造没有来源的耗时，并混淆启动调用与后台任务；只消费原生进度，后台启动调用收到结果后即结束。

## Consequences

停止、失败和结果缺失不再共用同一状态，已完成的后台启动调用不会因后台任务仍存在而重新运行。最后一次进度只表示观测值，不冒充最终耗时；没有数据时保持未知。消费者必须处理全部终态，未完成项仍可直接查看最后输出。生命周期边界由[驱动测试](../../../../src/server/drivers/codex/codex-driver.test.ts)和[时间线测试](../../../../src/web/store.test.ts)约束。
