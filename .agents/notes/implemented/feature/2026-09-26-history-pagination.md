# Agent Note: 会话历史从尾部按需分页

Status: implemented

## Problem

手机重新打开长会话时，全量历史传输、时间线重建和渲染阻塞首屏。完整下载子任务历史也使只查看主对话的用户承担不必要的等待；通过新增持久化历史副本解决会增加同步与状态维护成本。

## Decision

会话先呈现最近若干轮，向上阅读时才加载更早内容，子任务内容在选中时加载。历史分页与实时订阅独立，前插旧内容保留阅读锚点，旧页不能覆盖已有实时内容。Codex 使用原生轮次游标，Claude 复用已有完整内存历史并在请求时计算边界；只为 Claude 增加一个可为空的历史代次，兼作完整历史已加载标记，不保存轮次索引、客户端分页进度、磁盘历史副本或浏览器持久缓存。重建历史使旧游标失效，客户端重新获取尾页。

Claude 重复打开复用 daemon 内存，原生客户端修改通过显式刷新校准；读取失败不建立已加载标记，daemon 重启后重新读取。分页返回前合并重复流式状态，保留完整消息和工具生命周期。数据库 schema 保持不变。此决策部分替代[会话切换缓存](../bug-fix/2026-09-22-session-switching.md)的全量刷新方式，保留其有界视图缓存与阅读状态；[原生历史归属](../simplification/2026-09-17-session-state-without-turn-ledger.md)及[子任务流式基线](../bug-fix/2026-09-22-codex-background-child-events.md)继续有效，没有完整替代的记录。

## Alternatives considered

**服务端持久化时间线并维护增量同步日志：** 可以改善冷读取，但增加第二份历史及其一致性成本，超过当前需要。

**浏览器持久化全部会话：** 重复访问可加速，但首次访问和缓存被清理后仍需承担全量加载，不解决首屏工作量随整个历史增长的问题。

**为 Claude 保存轮次索引：** 能减少分页扫描，但增加状态维护；当前选择按请求计算，接受服务端扫描成本。

## Consequences

首屏快照仍通过 WebSocket 订阅返回，后续分页通过 HTTP 读取。WebSocket 单独启用消息压缩，因为 HTTP 压缩不覆盖该通道；小消息跳过压缩，并禁用跨消息字典复用，以压缩计算成本换取大快照传输量下降，同时限制每连接的字典保留。压缩不改变分页边界，也不解决单轮过大或前端渲染成本。

手机首屏与翻页只处理当前需要的历史，Claude 冷读取和完整内存占用仍然存在，单轮巨大的工具输出也不因轮次分页而被截断。Codex 原生分页能力成为读取要求，不引入全量读取兼容分支。Claude 外部修改不再通过每次订阅自动校准，用户需显式刷新；历史重建后的失效游标不能继续拼接旧页。分页、实时更新、子任务恢复及移动端阅读位置由[服务端测试](../../../../src/server/history-page.test.ts)与[浏览器测试](../../../../test/e2e/history-pagination.spec.ts)约束。
