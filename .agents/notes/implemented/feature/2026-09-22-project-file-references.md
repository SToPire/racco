# Agent Note: 对话文件引用进入项目只读预览

Status: implemented

## Problem

对话和文件变更已包含项目路径，但用户必须手动在 Files 中重新寻找文件，带行号的引用也不能直接定位。把相对路径交给浏览器导航会误入应用路由，跟随当前侧栏项目解释路径又可能打开另一个项目的同名文件。

## Decision

Markdown 的项目文件链接与文件变更路径打开已有 Files 预览，复用同文件标签。读取边界固定为当前会话项目，相对路径则按产出内容的 Agent 工作目录解析，再校验目标仍在项目内；目录未知时不猜测相对路径，项目内绝对路径仍可访问。Markdown 支持文本文件的明确行号定位，工具返回的路径则按原始文件名处理，不把文件名字符解释成 URL。外部网页链接保持普通链接，越界或无效引用显示不可用。

读取继续经过 daemon 的项目文件 API，由服务端校验真实路径与符号链接边界。定位仅移动只读文件预览并标记目标行，缺失文件和不存在的行明确反馈，不补造历史内容或默默改指另一个文件。本决策补充[项目 Dock](2026-09-18-project-session-import.md)和[工具结果详情](2026-09-22-tool-inspector-results.md)，保留它们的项目归属与按需查看取舍，没有替代现有记录。

## Alternatives considered

**让浏览器直接导航本地路径：** 不能可靠地读取 daemon 主机文件，也无法保持项目边界和现有文件标签。

**按当前侧栏项目、主 Agent 工作目录或仅按文件名匹配：** 操作更容易接入，但侧栏与会话可以属于不同项目，子 Agent 也可能使用不同目录，同名文件会造成错误定位。

**增加原生文件打开或编辑器：** 超出只读查看引用的需要，还会改变现有统一网页文件浏览和 Linux daemon 的职责边界。

## Consequences

用户可以从对话或变更详情进入当前项目文件和指定行。预览反映 daemon 文件系统的当前内容；历史引用可能已经失效，删除文件仍应阅读已有差异。未显式提供链接的普通文本和代码片段不自动猜测为文件，项目外路径也不会扩展读取范围。
