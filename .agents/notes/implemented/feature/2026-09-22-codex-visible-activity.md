# Agent Note: Codex 展示性过程保留原生语义

Status: implemented

## Problem

Codex 已提供公开思考摘要、方案正文、执行清单和回复阶段，但界面丢弃摘要、把方案当作普通回复，无法区分正在汇报进展和给出最终答复。只增加工具摘要不能补全这些过程信息。

## Decision

时间线分别承载公开思考摘要、方案正文、执行清单和原生回复阶段，主对话与子 Agent 采用同一投影。仅展示 Provider 的公开摘要，原始推理内容不进入共享事件或前端。可恢复的正文在实时增量与原生历史中保持相同类型，完整项覆盖流式项；中断和失败保留已收到内容并标明终止。

本决策落实[Chat 可理解过程提案](2026-09-22-chat-observable-work.md)中的 Codex 展示性事件范围，其余展示与交互决策由各自记录持有。相关[Claude 流式输出](../bug-fix/2026-09-18-claude-streaming-output.md)继续持有其 Provider 特有的内容块归属与重试规则；[不保留逐轮执行记录](../simplification/2026-09-17-session-state-without-turn-ledger.md)的历史归属保持有效，不为过程展示增加执行账本。

## Alternatives considered

**继续把所有过程当作助手文本：** 可以复用普通消息样式，但用户仍无法区分方案、执行状态和最终答复，执行清单的更新也会变成重复消息。

**根据正文猜测阶段或重新生成摘要：** 增加推断错误与模型开销；原生未报告的阶段保持未知，未报告的摘要保持缺失。

**为了恢复所有进度而另存逐轮历史：** 改变现有历史所有权，并引入第二份事实来源；原生历史不包含的执行清单限定为实时状态。

## Consequences

用户可以读取当前工作方向、方案和执行进度，并按需展开公开摘要。执行清单与方案正文是不同信息：前者来自原生实时更新，重新读取原生历史时不承诺恢复；后者及公开摘要随原生项恢复。共享联合类型增加展示分支，后续消费者必须明确处理其语义，不能退化成工具或普通回复。投影与流式一致性由[映射测试](../../../../src/server/drivers/codex/activity-mapper.test.ts)和[驱动测试](../../../../src/server/drivers/codex/codex-driver.test.ts)约束。
