# Agent Note: 按项目浏览并显式导入原生会话

Status: implemented

## Problem

用户需要在选定项目中找到已在 Codex 或 Claude 创建的会话，并在 Racco 继续工作。仅提供按原生 ID 调用的导入接口要求用户自行寻找标识，无法在网页内完成这项操作。

## Decision

项目会话与文件共用右侧可折叠 Dock，以两个常驻按钮切换。会话发现只在用户打开面板或操作列表时，通过 Provider 原生能力按项目目录读取分页元数据；选择导入才登记 Racco 会话，原生历史继续由 Provider 保存。保留已导入标记与直接打开入口，避免重复登记。发现边界采用规范化目录，且不把子 Agent 作为独立会话导入。[Worktree 管理](../architecture/2026-09-20-git-worktree-management.md)把该边界从项目目录改为所属 Worktree 目录：同一项目下不同 Worktree 的会话各自独立发现，记录于此的其余约束不变。

导入只读取历史，不取得执行所有权。续聊时遵守 Provider 的原生互斥规则，Codex 会话已被其他进程持有时提示用户释放，不自行抢占。候选列表和导入允许传递原生标识，后续对话交互仍使用 Racco ID。

本决策扩展原有定点导入的网页入口，不替代现有 Agent Note。[会话状态简化](../simplification/2026-09-17-session-state-without-turn-ledger.md)的原生历史归属和无逐轮账本决策，以及[模型选择](2026-09-17-composer-model-selector.md)的首次发送配置要求继续有效。

## Alternatives considered

**自动发现并登记所有历史：** 会让其他项目和无关会话进入当前目录，增加后台扫描与状态维护成本；用户显式选择更符合自管理项目边界。

**继续只提供按 ID 导入：** 实现简单，但无法让用户在网页内发现所需会话。

**浏览时直接 resume：** 将查看历史变成执行权接管，会与外部客户端冲突；读取和执行保持独立。

## Consequences

用户可以在同一工作区完成发现、导入和续聊，切换右侧功能不丢失同项目的文件浏览状态。候选列表是按需取得的元数据快照，外部变化需要刷新；导入成功不保证随后能取得写入权。后台和普通项目／会话列表读取不新增历史发现，Racco 持久化仍只随已登记项目与会话增长。会话的磁盘文件清理由[彻底删除原生会话文件](2026-09-19-native-session-delete.md)另行提供，本记录的只读浏览约束不变。
