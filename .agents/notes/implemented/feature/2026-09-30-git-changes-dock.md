# Agent Note: Worktree 当前 Git 修改只读 Dock

Status: implemented

## Problem

已有文件浏览和工具差异详情无法完整查看 Worktree 当前未提交修改，shell、外部编辑与后续撤销尤其不能靠 Provider 事件重建。用户需要在网页中直接审阅实际文件变化，且不能把会话目录与手动选择的另一个 Worktree 混淆。

## Decision

现有项目 Dock 提供“Git 修改”，以所选 Worktree 的 Git 与文件系统为事实来源，分别展示冲突、未暂存、已暂存与未跟踪，只读按需加载单文件差异。遵守 Git ignore，提交后的改动离开当前列表；不把原有脏文件、外部编辑或工具事件归因为本轮 AI，不引入逐轮快照或持久账本。

下方独立的[提交历史区域](2026-10-08-git-history-dock.md)持有固定引用快照、滚动追加与历史树比较；当前修改继续使用本记录的工作区基线，两者各自刷新并保留阅读位置。

界面沿用 Dock 的目录选择、移动端覆盖及收起后焦点返回，显示分支或 detached HEAD、所选根目录与最近成功读取时间。文件列表置于差异上方，避免窄栏再分成左右两列；同一文件可同时属于已暂存与未暂存，选择身份包含 Worktree、分组、新路径及重命名旧路径。详情取得完整文本补丁后才显示该项增删行数，不批量计算列表行数，也不把非文本或不完整结果显示为零。

未暂存差异比较 index 与工作文件，已暂存比较 HEAD 与 index；unborn 的暂存内容与空树比较，未跟踪文本与空文件比较。两种基线独立保留，工作文件改回 HEAD 也不会吞掉相互抵消的暂存和未暂存变化，intent-to-add 不虚构已暂存全文。统一使用合法 unified diff，保留空行和末尾换行状态；重命名作为一个逻辑条目，可在同一基线下展示旧文件删除及新文件新增两个文件段。冲突只展示未合并状态和当前文件入口，不生成 combined diff；二进制、空文件、权限与类型变化明确表达，子模块只显示 gitlink 与脏状态而不递归读取，LFS 指针只展示本地已有内容而不下载实际文件。

服务端在详情读取时重新证明文件和分组仍存在，重命名旧路径来自当前 Git 状态；客户端确认响应的目录、分组、新旧路径与选择一致，不展示错配内容。“打开当前文件”绑定所选 Dock Worktree 的目标新路径，删除或不可用目标禁用，旧路径仅作差异元数据，不通过会话文件引用改变目录归属。

读取遵守同源和已登记目录边界，规范化后的 Git 顶层根必须恰好等于所选根，导入仓库子目录不会扩大为父仓库权限。请求拒绝绝对文件路径、NUL、越界及未知字段，路径使用 literal pathspec；已删除条目依靠已确认的 Git 状态和对象读取，不要求工作文件存在。Git 通过固定参数启动，禁用 shell、pager、external diff、textconv 和文件系统监视程序，不执行仓库指定的展示程序。路径保留 NUL 分隔并严格解码 UTF-8，不能按空白拆分或用替换字符查询其他文件；补丁头的路径转义不成为文件读取依据。

工作文件读取检查父目录和打开后的文件描述符仍位于根内，拒绝 FIFO、设备及其他非普通文件；符号链接只比较链接字符串，不跟随目标。文本与对象大小在读取前检查，实际读取仍受容量限制，Git 输出流超限即终止。当前限额为修改条目 1000 项、Git 标准输出 8 MiB、单次进程 15 秒、单文件文本及补丁 2 MiB、补丁 20000 行；超限返回明确原因，不把截断列表或补丁当作完整结果。

刷新时机由[用户导航和手动刷新](../simplification/2026-09-30-git-dock-manual-refresh.md)持有：列表在进入面板、切换目录或手动刷新时读取，选择文件只读该项差异，成功列表刷新同时重读选中详情，即使状态字符未变。读取时间与过期状态显式可见，暂态失败保留同一目录的成功内容和阅读位置，权限撤销或目录失效清空内容，单个条目失效只清除对应详情；关闭请求与迟到响应不能把旧身份的结果展示为当前结果。失败不等于无修改，徽标只反映最近成功读取，关闭面板不后台扫描。

服务端同 Worktree 只允许一个活跃读取并合并列表请求，忙碌详情明确返回变化中而不排队；Git 内容读取不刷新 Worktree 目录清单，也不触发其他 Worktree 的脏状态扫描。读取前后以 HEAD、index、Git 状态和选中文件元数据尽力检测外部修改，检测到变化最多重试一次，仍变化则明确失败，不把旧详情标记为新快照。

本决策扩展[项目 Dock](2026-09-18-project-session-import.md)的面板种类，原有文件和会话职责仍有效；沿用[Worktree 管理](../architecture/2026-09-20-git-worktree-management.md)的目录身份、[统一差异语义](../bug-fix/2026-09-22-file-change-diff-contract.md)的展示规则和[文件引用边界](2026-09-22-project-file-references.md)的安全读取要求。[不保留逐轮记录](../simplification/2026-09-17-session-state-without-turn-ledger.md)继续有效；此次局部替代检查没有完整被替代或应归档的记录。

## Alternatives considered

**聚合 Provider 文件修改事件：** 无法覆盖 shell 和外部修改，历史操作也不等于当前文件结果，不能作为当前 Git 状态来源。

**只展示相对 HEAD 的净差异：** 会丢失暂存与工作区互相抵消的两份变化，也不能表达未跟踪和未合并状态；分别查看两个当前基线更可靠。

**严格按 AI 轮次保存文件基线：** 可以支持不同的轮次比较需求，但需要保存原有脏内容、index 和未跟踪内容，处理并发修改及重启，不属于当前未提交修改查看器；不能用 HEAD 或文件路径事件冒充精确归因。

## Consequences

用户可在所选 Worktree 审阅各组实际修改，部分暂存、冲突、空文件、删除和非文本类型不会误显示为无修改。查看不暂存、不回滚、不提交，不改变分支；窄屏仍能完成文件选择、差异阅读和返回。选择身份及响应校验增加了状态处理成本，但避免跨 Worktree、跨基线或重命名变化后读错文件。

多次 Git 和文件读取只能尽力检测外部并发，不能承诺原子快照或修改归因；资源上限也意味着大仓库或超大改动可能无法完整展示。无效 UTF-8 文件名和文本明确反馈不可展示，不能为可见性牺牲路径准确性。严格轮次范围若成为需求，需重新评估基线所有权与存储代价。

测试部署使用独立构建快照、systemd 用户服务、端口、Racco 状态与新建 Worktree 根目录，并隔离 Provider 本地会话目录；只复用现有登录配置的独立副本，不复制正式会话历史。Tailscale Serve 的单独 HTTPS 端口提供 tailnet 内访问，不改变正式服务的入口；Git 修改仍取决于用户显式导入的目录。这种隔离需要额外构建和运行资源，但避免预览影响正式会话与服务状态。
