# Agent Note: Racco 产品标识统一

Status: implemented

## Problem

用户已经选定 Racco 名称和浣熊标志，多 Agent 工作台需要在界面、代码、部署入口与使用文档中呈现一致身份，避免运行标识和界面品牌脱节。

## Decision

产品名称统一为 Racco，代码符号、包名、配置入口、服务名、状态文件和脚本环境变量同步采用当前名称，不保留旧名称别名或双路径读取。安装位置由用户数据目录下的固定入口链接到仓库，让 systemd 服务不依赖检出目录的名字；项目路径仍以真实文件系统身份为准。

WebUI 左上角和首页的新建对话输入页使用[已选定的 SVG 标志](2026-09-18-racco-logo-assets.md)，并根据系统主题选择字标颜色；浏览器标题与 favicon 使用同一品牌。[首页输入统一](../simplification/2026-09-18-home-composer.md)移除独立的首页空状态，品牌展示继续由输入页承载。标志由构建工具直接引用原始 SVG，纳入源码摘要，避免资产修改被部署校验遗漏。安装步骤见[README](../../../../README.md)。

本记录落实图形资产记录中的产品集成范围，保留其造型、色彩、单色与小尺寸取舍；其他会话和 Provider 记录的决策不变，只更新当前名称与链接。

## Alternatives considered

**仅修改界面文字：** 配置、进程和工具仍呈现另一套身份，会增加安装与排错成本；统一替换所有自有入口。

**保留旧名称作为别名：** 会形成两套配置和启动方式，违背项目只有一个当前契约的约束。

**在组件中复制标志路径：** 容易与设计源文件产生差异；直接引用 SVG 资产并由构建工具处理资源。

## Consequences

后续安装和脚本只使用 Racco 标识。身份更名不改变数据库结构、原生会话 ID 或项目目录语义；部署中的文件改名应在停止进程并备份后完成，启动仍严格校验当前 schema。标志资产变化会使构建摘要变化，浅色、深色与窄屏展示使用同一组源资产。
