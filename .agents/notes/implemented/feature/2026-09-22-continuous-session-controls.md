# Agent Note: 跨视图保留会话控制与运行中草稿

Status: implemented

## Problem

Trajectory 隐藏待回答问题和停止入口，用户查看执行详情时必须返回 Chat 才能继续任务。运行期间整个输入框不可编辑，也阻止用户准备下一条消息；切换视图还会丢失未提交的输入。

## Decision

Chat 与 Trajectory 共用持续挂载的问答、停止和消息输入区，切换视图保留草稿与未提交回答。问题区域限制占用高度，使轨迹搜索和详情仍可使用。任务运行中或等待回答时允许编辑草稿，但发送和模型选择继续禁用，只有任务结束后才能显式发送；不增加消息排队、自动补发或运行中指令能力。

文本编辑与发送可用性分别表达。压缩、会话或连接不可用以及发送尚未确认期间仍锁定文本；发送确认前不能开始编辑下一份草稿，避免旧请求完成时清空新内容。本决策补充现有交互，不替代[压缩期间禁用输入](2026-09-17-compaction-busy-feedback.md)、[仅保留用户问答](../simplification/2026-09-19-question-only-interactions.md)和[无逐轮执行记录](../simplification/2026-09-17-session-state-without-turn-ledger.md)的执行与恢复边界。新建会话流程不变。

## Alternatives considered

**继续把全部控制放在 Chat：** 轨迹界面更空，但等待输入或需要停止时会打断查看过程，也让可用操作取决于阅读视图。

**运行期间允许直接发送或自动排队：** 需要额外的执行契约和队列语义；准备草稿只改变本地编辑能力，不宣称后端具有当前未提供的能力。

**两种视图分别创建输入与问答区：** 容易在切换时丢失或分裂未提交内容；共享持续存在的交互区使阅读导航不会改变任务控制状态。

## Consequences

用户可以一边查看轨迹一边回答问题、停止任务或准备下一条消息。共享输入区占用部分轨迹高度，长问题列表需要在其区域内滚动。草稿只在当前页面保留，不承诺刷新后恢复；压缩和未确认发送的禁用行为继续优先于草稿准备。
