# Agent Note: Git Dock 按需浏览提交历史与提交差异

Status: implemented

## Problem

当前 Git Dock 只展示未提交状态，改动一旦提交便无法在网页中回看。用户需要在 Source Control 面板中保留当前修改，同时按需展开下方的历史区域，从提交图识别分叉与合并并审阅提交差异。历史列表必须有独立滚动空间，不能随着条目增长撑高面板或一次读取大量历史。

## Decision

在现有 Source Control（Git）面板的当前修改内容下方提供“提交历史”可折叠区域，默认折叠、首次展开才读取。展开历史不收起或替换上方当前修改；历史标题始终留在面板内，不随上方长列表滚走。展开后历史占据有界高度，初始约为面板可用内容高度的三分之一，并可通过上下分隔条调整；上方保留可操作空间。上下内容独立滚动，历史区域有自己的纵向滚动条，新增提交不会撑高整个 Dock，手机端也限制在可用视口内。

```text
Source Control                 [Worktree ▾] [刷新修改]
当前修改
  Unstaged / 已暂存 / Untracked / 冲突
  文件列表与差异                 ↕ 上方阅读区域
───────────────────────────────────────────────
▾ 提交历史                  [当前分支 ▾] [刷新历史]
  ● 提交标题                       短 SHA      │
  │ [main] [origin/main]                       │
  │                                           │ 独立滚动条
  ● 更早的提交                                │
  滚动接近底部时加载下一批                     ↓
```

默认范围已确认采用所选 Worktree 当前分支，可切换全部本地和已知远端分支；当前分支包含全部可达祖先和合入支线，detached HEAD 按当前提交追溯。全部分支范围也包含所选 Worktree 的 detached HEAD，tag 仅作标签，stash 和 reflog 不混入。首版只读查看，不扩展为提交、切换或重写历史工具。

提交图依据真实父对象关系和拓扑顺序绘制分叉、合并及跨批连接。列表采用紧凑单行，标题超长省略，8 位短 SHA 固定在条目右侧，点击该 ID 复制完整 SHA，并显示成功或失败反馈；复制操作独立于打开提交详情，支持鼠标与键盘。列表不显示“已加载条数 · 分支名”常驻摘要。作者和日期不另占行，鼠标悬停条目时通过浏览器原生提示展示完整标题、SHA、Author、Author Date 和 Commit Date，使用已加载数据，不因悬停或复制发起读取。带引用的提交在标题下方展示 Refs 胶囊标签，分别呈现 HEAD、本地分支、远端分支和 tag，不在提交悬停提示中重复引用；多个标签可在该行横向滚动，超长名称省略并由标签悬停提示提供完整名称。无引用条目保持 32px 单行，有引用条目仅增加 28px 标签区；图线、虚拟列表、视口补读和键盘定位共用累计高度，节点保持与标题对齐，追加不改变已有条目的位置。未加载祖先和浅克隆边界不能画成根提交，边界父不参与普通遍历边的先后约束。纵向延续线使用共享跨度，只有可见行生成绘制边，避免逐提交复制全部活跃图线；图有独立的 lane 与边预算，超限明确提示并保留提交列表与详情，不绘制缺失连线的假图。阅读层级为“提交图 → 提交信息与文件列表 → 选中文件差异”，均在下方历史区域内部切换，不改变上方当前修改的选择或位置。文件补丁按选择读取；返回图恢复选中行、已加载批次及历史滚动位置，位置恢复不视为新的加载操作。手机保留相同层级和可达的返回入口，图和代码溢出只在各自容器内滚动。

提交详情头部仅展示标题、提交者和提交时间，不重复展示作者时间、提交 SHA、普通提交的比较基线或完整提交说明，以便把空间留给文件列表；合并提交的父提交选择作为单独的比较操作保留在文件列表上方。

历史差异从提交树生成，独立于 HEAD、index 和工作文件：普通提交与父提交比较，确认原始对象无父提交的根提交与空树比较；合并提交默认与第一父提交比较，并允许选择任一实际父提交，切换基线清除旧文件选择。复用现有 unified diff 展示，保留重命名、新增、删除、类型或权限变化、二进制、符号链接、子模块和空提交的真实含义；缺失父对象明确显示基线不可用，不能冒充根提交或空差异。

首次及每次追加读取 15 条，用户在历史列表自己的滚动容器内接近底部时自动追加下一批，不提供常规“加载更多”翻页按钮，也不监听页面、当前修改或聊天区域的滚动。首次结果不足以填满历史视口，或持续可见的区域被扩大后失去滚动空间时，以有界补读恢复滚动能力；每次至多追加三批，不能形成连续预读。恢复已有视图的首次尺寸测量不授予补读额度。一次只允许一个追加请求，同一 cursor 的重复触发合并，仅完整成功响应后推进 cursor，失败或取消保留原位置。追加完成后保留可见提交与滚动锚点，不回到顶部、不重排已有图线。暂态失败保留已有内容并显示显式“重试”，不自动重试；无下一批时显示“已到历史末尾”并停止触发。

滚动追加仍由有界 cursor 分页提供，固定引用起点 OID、标签和浅克隆边界的短期快照，避免 commit、amend、rebase 或 fetch 把两次历史混到同一图中。引用读取期间发生变化时进行有界重试，不能发布混合快照。Git 仍是事实来源，不新增持久历史副本，不隐式 fetch 或补下载对象。同一 Worktree 内返回、折叠再展开或重入 Dock 复用原快照；切换历史范围和显式刷新历史才重建，成功后清空历史选择并回到该列表顶部，失败保留同一身份的旧内容并标记过期。Source Control 顶部刷新只更新当前修改，历史标题的刷新按钮只重建历史快照，两者不重置对方的选择或滚动位置。切换 Worktree 清空历史与选择并恢复折叠；快照过期、被淘汰、服务重启或浅克隆边界变化要求显式刷新，不自动重置追加结果。不轮询或随窗口焦点读取；滚动追加属于用户发起的读取，不刷新已有提交或引用标签。

读取和缓存有明确资源边界。浏览器只保留当前范围最多 5000 条或 8 MiB 的历史，补丁采用独立有界缓存；服务端分别限制快照容量和闲置期限，其完整元数据计量可早于浏览器摘要达到上限。任一端超限都保留已读内容、停止自动追加、明确显示容量终态，不误报历史末尾，也不提供必然再次超限的重试。Git 输出、文件、补丁和执行时间沿用有界读取规则，不把截断结果伪装完整。

历史和当前修改共用所选 Worktree 的活跃读取限制，客户端串行调度两个区域的读取；显式文件或提交选择保留最近一次有效意图，重复滚动合并为当前快照的一次待追加，不建立无界队列。折叠历史或进入提交详情时取消未完成列表请求；折叠历史还取消它的详情请求，上方当前修改继续可用，关闭整个 Dock 才取消两区读取。底层任务退出后才释放占用，短暂繁忙明确提供局部重试；详情或补丁重试不重建历史列表、不清除滚动位置，成功后清除该操作的错误与忙碌状态。目录权限、登记或快照失效才上报历史所有者；暂态错误保留同一身份的内容，取消或切换后的迟到响应不得追加到新视图或展示另一个提交的文件。

服务端继续验证登记 Worktree 和真实仓库根目录，只允许读取当前快照已加载的提交及其实际父基线，文件必须属于该次树比较。历史读取使用固定 Git 参数并禁用外部 diff、textconv、replace refs 和隐式对象下载，差异属性来自所选提交而非工作文件。对象按字节长度分帧，父关系、树标识与时间严格校验；消息作为纯文本展示，符号链接只展示链接内容。这些边界避免历史入口扩大目录权限或执行仓库指定程序。

作者或提交说明不能按 UTF-8 显示时，以 `textUnavailableReason` 明确表示缺失并保留可读的提交身份、拓扑、日期及树差异，不让单个展示字段阻断更早历史，也不猜测旧字符集或用替换字符解释路径。被省略的原始大文本不被短字段的字符串切片留在缓存中。非 UTF-8 引用名和路径仍明确拒绝读取，不能为了继续浏览而读错身份。

本决策扩展[当前 Git 修改 Dock](2026-09-30-git-changes-dock.md)，保留其工作区状态、只读和目录边界；[手动刷新](../simplification/2026-09-30-git-dock-manual-refresh.md)继续约束当前修改，历史另以固定对象快照保留阅读位置，共同保持按需读取；[统一差异语义](../bug-fix/2026-09-22-file-change-diff-contract.md)继续有效。没有完整替代或应归档项；Git 对象读取也不改变[Provider 历史归属](../simplification/2026-09-17-session-state-without-turn-ledger.md)。

## Alternatives considered

**只显示线性提交清单：** 实现简单，但无法解释用户希望查看的分叉和合并；本次采用可分页的真实提交图。

**每页读取当时的分支名：** 无需保存 refs 快照，但 amend、rebase 或 fetch 会改变遍历起点，导致分页重复或漏项；固定起点以短期资源占用换取一致阅读。

**当前修改和历史互斥切换：** 能把全部空间交给单一视图，但查看历史时会隐藏当前修改，不符合在 Source Control 下方独立展开历史的浏览方式；采用上下并存、各自滚动的布局。

**每次加载 50 条并要求点击翻页：** 请求次数较少，但首次读取偏多且打断连续浏览；采用较小批次随历史区域滚动追加，在失败时才保留显式重试入口。

## Consequences

用户能在同一面板中审阅当前修改与历史提交，两者保持各自的选择和阅读位置；历史重写与错误不会把不同快照混在一起。代价是两个独立滚动区域及更明确的读取状态管理，小批次也增加请求次数。[浏览器交互](../../../../test/e2e/git-history.spec.ts)、[历史读取](../../../../src/server/git-changes/history.test.ts)和[提交图](../../../../src/web/commit-graph.test.ts)共同约束这些边界。

上下独立滚动区需要明确高度与触控边界，避免手机滚动穿透、历史区域挤占当前修改或高度变化连续触发加载。小批次会增加请求次数，拓扑图的跨批 lane、滚动锚点和多父合并需要专门验证；大量分支会增加横向宽度。固定起点的分页仍可能在大偏移遍历时超时，首版缓存上限也限制一次可浏览的历史深度，更深读取需要后续范围筛选或分页策略扩展。远端跟踪引用只反映本地已有状态，浅克隆或被回收对象可能无法比较；界面必须清楚表达边界而不隐式联网。首版只读查看，增加 Git 写操作需要另行设计执行与确认语义。
