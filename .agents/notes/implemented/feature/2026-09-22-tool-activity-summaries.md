# Agent Note: 工具活动摘要保持可见

Status: implemented

## Problem

主 Chat 把工具调用压缩成数量，展开后仍只显示工具名和状态。用户无法快速知道操作对象，运行与失败信息也被隐藏；子 Agent 和轨迹对同一工具使用不同摘要规则。

## Decision

各对话入口共用工具展示投影，事实来源由 [Driver ToolFacts](../architecture/2026-10-02-tool-facts-boundary.md)统一，优先采用原生描述、命令动作分类、路径和查询，无法识别的调用保留工具名及简短原始输入。名称翻译和动作类别命名由[保留工具原名](../simplification/2026-09-22-original-tool-names.md)部分替代；动作分类仍用于摘要。动作与结果分开；退出码、耗时和 diff 统计只取实际已有字段，不从命令推断测试通过或任务完成。原先按状态及选中项保留常显调用的默认可见性规则，由[按时间线折叠](../bug-fix/2026-09-29-chronological-tool-folding.md)部分替代：Chat 折叠连续历史前缀，近期后缀常显，折叠标题按工具原名计数。

主对话和子对话共用 SVG 工具图标，按明确工具名选择对应图形，未识别的工具统一使用扳手。图标辅助辨认，工具原名及命名空间仍是身份依据；不根据命令内容、参数或名称片段猜测未知工具的类型。

本记录落实[可理解执行过程提案](2026-09-22-chat-observable-work.md)的工具展示范围。检查相关的会话、流式与交互记录后，没有既有工具摘要决策需要替代；Provider 原生历史归属和仅用户问答的边界保持有效。

[工具终态与进度](2026-09-22-tool-lifecycle-states.md)补充中断和结果未知的区分，原生进度与最终耗时保持不同含义；本记录继续持有动作摘要、紧凑布局与按需详情的决定。

## Alternatives considered

**保留数量折叠，仅增加详情字段：** 有用信息仍需多次操作才能读到，无法解决默认视图的可理解性。

**默认展开完整日志或为每次调用生成模型摘要：** 前者淹没对话，后者增加成本及解释偏差；已有结构足以提供首层摘要，完整输入和输出仍由详情承载。

## Consequences

主 Chat 与子 Agent、轨迹对工具的描述一致，可见工具行可直接阅读运行输出和失败摘录，较早调用需展开历史查看。成功输出不会自动解释成业务结论，未知工具只显示有据可查的参数。长原始数据继续保留在工具详情，不因摘要截短而丢弃。

紧凑工具行限制名称宽度，长 MCP 名称不能挤掉动作和状态；完整名称仍可在标题提示和工具详情读取。

工具名、对象和已有结果统计横向排列，缩小留白并弱化常驻边框；长摘要截断，完整内容仍由工具详情承载。可见工具行中的运行进度和错误、输出预览按需增加有限行数，无需打开详情即可阅读。这延续动作摘要的决定，参考 [DeepSeek Harness 的工具行](https://github.com/deepseek-ai/deepseek-harness/blob/c36a83ff6bb95e3f82cf79f9be7c724270a8aa61/packages/client/ui-tool/src/client/tool/components/ToolRow.module.css)以减少纵向占用；代价是长对象需要悬停或打开详情阅读。

Claude 编辑的变更规模与后台任务身份复用[原生结构化结果](../bug-fix/2026-09-22-claude-structured-tool-results.md)投影，可通过 Raw 核对；Output 则遵循[单一输出展示](../simplification/2026-09-22-single-tool-output.md)。任务启动调用完成仍不代表后台任务完成。

文件差异的原生格式归一、统计和着色边界由[统一差异语义](../bug-fix/2026-09-22-file-change-diff-contract.md)规定，原文符号和类似文件头的代码不能改变增删事实。
