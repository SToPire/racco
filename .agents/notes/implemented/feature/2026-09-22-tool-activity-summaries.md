# Agent Note: 工具活动摘要保持可见

Status: implemented

## Problem

主 Chat 把工具调用压缩成数量，展开后仍只显示工具名和状态。用户无法快速知道操作对象，运行与失败信息也被隐藏；子 Agent 和轨迹对同一工具使用不同摘要规则。

## Decision

各对话入口共用工具展示投影，优先采用原生描述、命令动作分类、路径和查询，无法识别的调用保留工具名及简短原始输入。动作与结果分开；退出码、耗时和 diff 统计只取实际已有字段，不从命令推断测试通过或任务完成。Chat 直接显示近期活动、运行项、失败项及选中项，较早的成功活动可以折叠，折叠标题保留动作类别。

本记录落实[可理解执行过程提案](2026-09-22-chat-observable-work.md)的工具展示范围。检查相关的会话、流式与交互记录后，没有既有工具摘要决策需要替代；Provider 原生历史归属和仅用户问答的边界保持有效。

[工具终态与进度](2026-09-22-tool-lifecycle-states.md)补充中断和结果未知的区分，原生进度与最终耗时保持不同含义；本记录继续持有动作摘要与默认可见性的决定。

## Alternatives considered

**保留数量折叠，仅增加详情字段：** 有用信息仍需多次操作才能读到，无法解决默认视图的可理解性。

**默认展开完整日志或为每次调用生成模型摘要：** 前者淹没对话，后者增加成本及解释偏差；已有结构足以提供首层摘要，完整输入和输出仍由详情承载。

## Consequences

主 Chat 与子 Agent、轨迹对工具的描述一致，运行输出和失败摘录可以直接阅读。可见行数随需要关注的活动增加；成功输出不会自动解释成业务结论，未知工具只显示有据可查的参数。长原始数据继续保留在工具详情，不因摘要截短而丢弃。

紧凑工具行限制名称宽度，长 MCP 名称不能挤掉动作和状态；完整名称仍可在标题提示和工具详情读取。

Claude 编辑的变更规模与后台任务身份复用[原生结构化结果](../bug-fix/2026-09-22-claude-structured-tool-results.md)投影，与详情采用同一事实来源；任务启动调用完成仍不代表后台任务完成。
