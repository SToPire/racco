# Agent Note: 输入框按轮选择主 Agent 模型与推理强度

Status: implemented

## Problem

用户需要在发送任务时选择主 Agent 的模型与推理强度，并在续聊、重连和 daemon 重启后保留执行意图。Provider 的模型能力、强度档位与恢复语义不同，仅保存浏览器下拉框状态无法保证一致性。

## Decision

新建和已有会话输入框将模型与推理强度收在同一个入口，减少工具栏占用；强度在模型弹层的二级菜单选择。新建页将项目选择放在输入框上方，项目与模型共用应用内浮层和键盘逻辑，避免原生菜单的风格差异；目录导入收在项目菜单底部。模型目录随页面上下文加载，不占用额外刷新入口。菜单条目保留原生名称和选中标记，避免描述文字干扰选择。整组配置随消息提交，Racco 保存会话偏好，Driver 使用随消息提交的配置快照并每轮显式传递。选项来自 Provider 客户端目录；同名强度不意味着跨模型等价。区分不支持调节与能力未知，建议值只初始化草稿。已有会话 Provider 固定，运行中的轮次和子 Agent 独立配置不受控件修改。消息契约由[共享协议](../../../../src/shared/protocol.ts)定义。

本记录统一持有输入框模型与强度配置的决策，保留 Racco 会话身份、原生历史归属和定点导入语义；同范围没有其他 Agent Note 被替代。遵守唯一当前协议和 schema，不为旧客户端或旧数据库增加兼容路径。

## Alternatives considered

**仅开放模型、固定使用默认强度：** 用户无法在同一模型上调节推理投入，不满足发送前控制模型与强度的需求。

**前端维护模型清单和统一强度菜单：** 选项会与 Provider 暴露的能力脱节，并允许不支持的模型／档位组合。

**分别更新模型、强度后再发送：** 多次请求之间可能被另一客户端插入操作；随消息携带完整配置可将执行意图绑定到同一请求。

**工具栏并列两个选择入口：** 调整强度少一次点击，但增加输入框底部占用；二级菜单保留控制能力并让常态界面更简洁。

## Consequences

非法配置在分配或执行前被拒绝，多客户端不能拼接配置或并发启动同一会话的两轮。首条消息接受时更新会话偏好与生命周期，保留可补完的创建窗口。原先逐轮持久化和重连重放的要求由[会话状态简化决策](../simplification/2026-09-17-session-state-without-turn-ledger.md)替代；消息配置仍随请求整体提交，创建请求身份仍由会话记录持有。目录查询不提交任务或持久化原生会话，能力未知时会阻止相应配置发送，换取失败时不偷偷换模型或降强度的保证。

Claude 使用每轮 SDK effort 并移除该 Query 的宿主 effort 环境覆盖，避免覆盖主 Agent 的选择或强制子 Agent 使用同一强度。SDK 目录表示客户端可提交的选项，自定义模型服务或代理仍可能归并档位；请求偏好不等于执行观测，不能用参数传递测试宣称最终推理策略已经验证。新 schema 按项目规则要求重建旧 Racco 状态，Provider 原生历史仍由 Provider 保留。
